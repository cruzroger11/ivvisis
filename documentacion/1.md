# Archivo 1: Distribución y Arquitectura del Sistema IVVI S.A.

Este documento detalla la estructura fundamental, las decisiones arquitectónicas y la organización modular del sistema de gestión industrial **IVVI S.A.** El diseño se centra en la robustez, la escalabilidad y el desacoplamiento de responsabilidades.

---

## 1. Arquitectura del Sistema

El sistema implementa una **Arquitectura de Tres Capas** (Three-Tier Architecture), que permite una separación clara entre la interfaz de usuario, el procesamiento de datos y el almacenamiento persistente.

### 1.1 Capa de Presentación (Frontend)
Constituida por el motor de plantillas **Jinja2** integrado en Flask. La interfaz sigue los principios de **SSR (Server-Side Rendering)** para garantizar un rendimiento óptimo en dispositivos de planta con recursos limitados.
*   **Aesthetics:** Se utiliza una estética de **Premium Glassmorphism** basada en variables CSS dinámicas, facilitando la adaptabilidad sensorial (Modo Claro/Oscuro).
*   **Interactividad:** Gestión asíncrona mediante JavaScript nativo para la recolección de telemetría y visualización de datos en tiempo real (Chart.js).

### 1.2 Capa de Lógica de Negocio (Backend)
El núcleo operativo reside en **Python 3.x** bajo el micro-framework **Flask**. 
*   **Patrón Service Layer:** Para evitar el antipatrón "Fat Controller", se ha implementado una capa de servicios especializada (`InventarioService`). Esta capa orquesta las reglas de negocio complejas, como la conversión de Toneladas a Litros y la atomicidad de la producción, de forma independiente a los controladores de rutas.
*   **Justificación Técnica:** Flask se eligió por su naturaleza modular y liviana, lo que permite al arquitecto de software tener control total sobre las dependencias e implementaciones sin el sobrecoste (overhead) de frameworks más pesados.

### 1.3 Capa de Persistencia (Base de Datos)
Utiliza **SQLite** como motor relacional, gestionado a través del ORM **SQLAlchemy**. Esta capa garantiza la **Soberanía de Datos** mediante un esquema *On-Premise*, eliminando la dependencia de servicios en la nube para procesos críticos de planta.

## 2. Organización y Flujo del Sistema

### 2.1 Estructura del Proyecto
El sistema se organiza bajo un esquema modular que facilita el mantenimiento preventivo y correctivo:
1.  **Directorio Principal (`app.py`):** Punto de entrada y configuración de middleware.
2.  **Modelos (`models.py`):** Definición del esquema relacional y lógica de integridad de datos.
3.  **Servicios/Utilidades (`utils/`):** Contiene la inteligencia computacional del sistema y generadores de reportes (PDF/Excel).
4.  **Plantillas (`templates/`):** Estructura visual segregada por módulos operativos.
5.  **Estáticos (`static/`):** Hoja de estilos centralizada y lógica de cliente.

### 2.2 Flujo General de Información
1.  **Ingreso de Datos:** El usuario interactúa con formularios industriales validados en tiempo real.
2.  **Procesamiento:** El controlador recibe la solicitud y delega la operación al `InventarioService`.
3.  **Validación Atómica:** Se verifica la disponibilidad de insumos y la integridad de las unidades de medida.
4.  **Persistencia y Auditoría:** La transacción se guarda en la base de datos y se dispara automáticamente un registro en el **Kárdex Forense**.

---

## 3. Módulos del Sistema y Funcionalidad

El sistema se divide en 6 áreas críticas de operación:
1.  **Dashboard de Telemetría:** Centralización de indicadores clave (KPIs), alertas de stock mínimo y estados financieros.
2.  **Gestión de Inventario Maestro:** Control centralizado de SKUs, marcas y categorías de insumo/producto terminado.
3.  **Módulo de Compras (Importación/Local):** Gestión multimoneda y motor de conversión TM a Litros para materia prima bulk.
4.  **Módulo de Producción (Envasado):** Transformación industrial atómica que vincula el consumo de materia prima con el egreso de envases vacíos.
5.  **Módulo de Ventas y Liquidación:** Emisión de facturas fiscales y actualización instantánea de las existencias disponibles.
6.  **Kárdex de Auditoría Forense:** Registro inalterable de cada micro-evento del sistema, garantizando la trazabilidad total del producto.

---
**Justificación de Diseño:** Esta distribución permite que el sistema IVVI S.A. sea robusto frente a fallos, fácil de auditar y preparado para una evolución futura hacia integraciones de IoT industrial.
